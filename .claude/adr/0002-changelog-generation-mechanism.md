# ADR 0002 — CHANGELOG.md generation mechanism per repo family

- **Status:** Accepted
- **Date:** 2026-07-22
- **Deciders:** Agentic Engineer (Spike [#2270](https://github.com/devantler-tech/monorepo/issues/2270); parent epic [#2269](https://github.com/devantler-tech/monorepo/issues/2269))
- **Issue:** [#2270](https://github.com/devantler-tech/monorepo/issues/2270)

> 🤖 Generated by the Agentic Engineer (Cursor cloud instance)

## Context

Epic [#2269](https://github.com/devantler-tech/monorepo/issues/2269) asks every portfolio repo to carry a
generated in-repo `CHANGELOG.md`. Today almost every public product repo runs **semantic-release**
via `devantler-tech/actions` `create-release.yaml` under a GitHub App token, with a `.releaserc` that
is either **commit-analyzer only** (org shared `.github/.releaserc`, ksail, go-template, aws, …) or
analyzer + **`@semantic-release/release-notes-generator`** + **`@semantic-release/github`** (platform,
templates, world-at-ruin). That path cuts tags and GitHub Release bodies; it never writes a file.

Only **`devantler-tech/actions`** has an in-repo `CHANGELOG.md`, produced by **release-please**
(`release-please-config.json`, `.release-please-manifest.json`, `active-release.yaml`).

Spike [#2270](https://github.com/devantler-tech/monorepo/issues/2270) must choose a mechanism that
survives branch protection and does not break KSail’s GoReleaser path or World at Ruin’s
draft-release → CD publish order.

## Options evaluated

1. **Extend semantic-release** with `@semantic-release/changelog` + `@semantic-release/git` (and
   optionally keep notes-generator).
2. **Converge on release-please** for version + changelog (the `actions` pattern).
3. **Hybrid** — release-please where the PR model fits; keep semantic-release tag cutting where CD
   depends on it, and land `CHANGELOG.md` through a protection-friendly path.

## Findings (verified 2026-07-22 via GitHub API)

### F1 — Protected `main` blocks `@semantic-release/git`

On `devantler-tech/ksail`, ruleset **Require a pull request before merging** (`id` 4134020) is
`enforcement: active` with **`bypass_actors: null`**. The same shape appears on `actions`. A plugin
that commits `CHANGELOG.md` straight to `main` therefore fails under live rules — not a hypothetical.
Widening bypass for a release App would be a maintainer ruleset change, not an agent default.

### F2 — release-please already works under those rules

`devantler-tech/actions` ships `CHANGELOG.md` through release-please PRs (`release-please--*` head
branches), then tags after merge. CI and dependency-review already special-case those PRs. This is
the only live in-repo changelog in the portfolio.

### F3 — semantic-release today never writes files

No sampled `.releaserc` enables `@semantic-release/changelog` or `@semantic-release/git`. Notes go to
GitHub Releases only (where notes-generator is present). Extending semantic-release *without* a git
commit still would not produce the epic’s in-repo file.

### F4 — KSail and World at Ruin are not plain release repos

- **KSail:** `release.yaml` → `create-release.yaml` (semantic-release / App token) → tag → GoReleaser
  CD / Homebrew cask path. Analyzer uses `feat!` → major. A blunt dual-bumper (semantic-release +
  release-please both owning version) would fight.
- **World at Ruin:** same create-release caller; `.releaserc` sets `draftRelease: true` so the tag
  triggers `cd.yaml`, which attaches artifacts and only then publishes the draft. Changelog work must
  preserve that order (documented in `release.yaml` header).

### F5 — Plain semantic-release family is the easy migrate set

Analyzer-only or notes-to-GitHub-only repos without a custom CD coupler (templates, several
libraries, aws, …) can copy the `actions` release-please layout with far less risk than KSail/WaR.

## Decision

**Choose option 3 — Hybrid — with release-please as the default in-repo CHANGELOG mechanism.**

| Family | Mechanism | Why |
|---|---|---|
| **Default** (templates, libraries, aws, and other plain create-release callers) | Migrate to **release-please** (`actions` pattern) | Proven under PR-required `main`; produces `CHANGELOG.md` without ruleset bypass |
| **`actions`** | Keep release-please | Already done |
| **KSail** | Keep semantic-release tag cutting for GoReleaser; add `CHANGELOG.md` via a **sequenced** release-please or changelog-PR design that does not dual-own semver | Protects `feat!` majors + cask CD; avoids `@semantic-release/git` |
| **World at Ruin** | Keep draft-release → CD publish; add `CHANGELOG.md` via the same protection-friendly PR path in a sequenced child | Must not break immutable-release ordering |
| **homebrew-tap / monorepo site** | Out of scope for product semver changelogs unless a later child says otherwise | Tap is cask-driven; monorepo has no product `.releaserc` |

**Rejected for portfolio-wide use:** extending semantic-release with `@semantic-release/git` under
current rulesets (F1). Revisit only if the maintainer adds an explicit, least-privilege bypass for
the release App.

## Consequences

- Follow-up implementation issues are filed under [#2269](https://github.com/devantler-tech/monorepo/issues/2269) (children of this Spike’s parent).
- Org shared `.github/.releaserc` stays analyzer-only until consumers migrate; do not add git plugins there.
- Agents must not “just enable changelog+git” on a create-release repo — that path is known-broken on protected `main`.
