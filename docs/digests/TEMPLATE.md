# How to write the maintainer digest

The digest is the maintainer's email about the agents' work. A workflow checks daily at 06:17 UTC
and sends only when unanswered asks remain, at most once per UTC day. It opens a combined digest as an
issue in this public repository and assigns it to him, and GitHub emails it to him. Write it for
one reader who has not followed the work since the previous digest.

## Where it goes

- Name the file `docs/digests/YYYY-MM-DD.md` after its UTC delivery date, for example
  `2026-10-24.md`. It covers work not already included in a delivered digest. Keep old week-named files as history.
- Merge it through an ordinary reviewed pull request before 06:17 UTC on its delivery date. If no
  pending reviewed summary passes its checks and fits in the email, the workflow sends only the
  open asks and says that the summary is missing.
- Copy everything below the line at the end of this guide into the file, then fill it in.
- **Quiet days send nothing.** Keep their dated summaries. The next email with an unanswered ask
  combines pending changelogs and records their exact hashes in its generated receipt. Large
  backlogs use batches that fit in an email, with a notice when more remains for later asks.
  A failed assignment or withheld summary never consumes a changelog. Do not hand-write receipts.
- **Never repeat answered asks.** A maintainer reply on the ask itself counts as a response.
  A numbered reply such as `1: B` on a delivered digest maps back to that digest's ask, even when
  the thread is closed. Agent output, other authors and quoted examples do not count as answers.

## Writing rules

- **Write for a person.** Use short sentences about what changed for someone, not about what the
  code does. A reader who has not followed the work should understand every line.
- **One change per line, with a link.** Every line ends with a link to its pull request or issue.
- **Group the work.** Under What shipped, group the lines by product or area, then by Fixed,
  Improved and New. Leave out a group that has nothing in it.
- **Give Agent Improver work its own heading**, after the products.
- **Leave Needs you to the workflow.** When it sends the digest, it fills that section with the asks
  open at that moment: each with its number, question, options, recommendation and what happens if
  it is unanswered, or one line saying nothing needs him. An ask filed after you wrote the file is
  still in it. `.claude/scripts/maintainer-digest.sh needs-you` shows what it will put there.
- **Keep it short.** Aim for a two-minute read. Leave out routine updates that change nothing a
  person would notice.
- **Say what changed in the digest itself.** When this template or these rules change, the next
  digest says so in one line, with the reason.

Write this: `Cluster backups now run every night instead of every week, so less work is lost if a
disk fails. ([#123](https://github.com/devantler-tech/platform/pull/123))`

Not this: `chore(deps): bump velero (#123)`

## Never include

This repository is public, and so is every digest and every reply to it. Never include:

- spend findings, prices, money amounts or invoices: they wait for the private Money digest;
- credentials, tokens or other secrets;
- hostnames, IP addresses or how a network is laid out;
- phone numbers or email addresses;
- personal or private detail about anyone;
- anything from a private repository.

`.claude/scripts/maintainer-digest.sh check` fails a file that shows any of these markers, and the
workflow holds back a file that fails it.

## How to reply

Reply to this email with an ask's number and your choice, for example `1: B`, or the number, a colon and your own words, for example `3: your words`.
Your reply posts publicly, as a comment on this issue in the public devantler-tech/monorepo repository.
