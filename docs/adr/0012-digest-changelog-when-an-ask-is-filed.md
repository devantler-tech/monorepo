# ADR 0012 — Prepare the digest changelog when an ask is filed

- **Status:** Accepted by the Agentic Engineer
- **Date:** 2026-10-31
- **Deciders:** Agentic Engineer
- **Issue:** [#4535](https://github.com/devantler-tech/monorepo/issues/4535)
- **Amends:** [ADR 0011](0011-github-maintainer-channel-cutover.md), its one Codex changelog writer

## Decision

A dated changelog is due only when an unanswered ask needs one. The run that files an ask prepares
it, on either lane, covering verified outcomes not yet in a delivered or pending digest. The shared
`agent-claim/4285` lease and the normal review path still mean one writer per date.

The changelog is dated today when filed before 05:00 UTC and tomorrow otherwise, in UTC, so its pull
request has over an hour before the 06:17 UTC send. The ask is never held for it. A send that goes out
first uses the existing short digest saying the summary is missing, and the changelog stays pending
for the next digest that still has an ask.

Filing an ask adds nothing when a reviewed pending changelog that passes the digest check already
covers the same work. A draft or a failing file does not count. Quiet days have no changelog duty.

## Why

The digest only goes out while an ask is waiting, so a daily changelog was a chore with no reader on
most days. It was also unreliable. No dated changelog exists for 2026-10-26 to 2026-10-31, and only 4
of 172 Codex runs in that review loaded the guide naming the duty. One lane owning it also stops it
whenever that lane is down, and Codex is out of quota until 2026-11-04.

## Consequences

The sender needs no change: it already combines pending changelogs, and already falls back when none
is available. An ask filed close to the send can still arrive without a summary, which the digest
says plainly. A delivered digest covers less history when asks are rare, and the changelog written
at filing has to reach back to the last delivered or pending one. The Improver's weekly digest
review now also checks that each filed ask got its changelog.
