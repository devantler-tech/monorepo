# ADR 0010 — Send the maintainer digest every third day

- **Status:** Accepted by direct maintainer direction
- **Date:** 2026-10-24
- **Deciders:** Maintainer; Agentic Engineer
- **Issue:** [#4475](https://github.com/devantler-tech/monorepo/issues/4475)

## Decision

Send the maintainer digest, including unresolved asks, every third UTC calendar day instead of
weekly. This supersedes only the weekly delivery cadence in [ADR 0009](0009-github-maintainer-asks-weekly-digest.md).
Its public-content boundary, GitHub notification delivery and reply rules still apply.

The workflow checks daily at 06:17 UTC. Its sender waits until three UTC dates have passed since
the newest bot-created digest assigned to the maintainer. Closed digests count too, so closing
one does not cause an early resend. A digest that GitHub never assigned does not suppress a retry.
A missed scheduled run can catch up at the next daily check. GitHub scheduling can be delayed;
the cadence is not an email delivery guarantee.

Summaries use their UTC delivery date as `docs/digests/YYYY-MM-DD.md`, and cover work since the
previous digest. Existing ISO-week files and ADR 0009 remain historical records. If a dated
summary is unavailable or fails its existing checks, the sender still includes the current
open asks and explains that the work summary is missing.
