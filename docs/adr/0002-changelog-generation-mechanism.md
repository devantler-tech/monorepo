# ADR 0002 — CHANGELOG.md generation mechanism per repo family

- **Status:** Accepted
- **Date:** 2026-07-22
- **Deciders:** Agentic Engineer (Spike [#2270](https://github.com/devantler-tech/monorepo/issues/2270); parent epic [#2269](https://github.com/devantler-tech/monorepo/issues/2269))
- **Issue:** [#2270](https://github.com/devantler-tech/monorepo/issues/2270)

> 🤖 Generated by the Agentic Engineer (Cursor cloud instance)

## Context

Epic [#2269](https://github.com/devantler-tech/monorepo/issues/2269) requires a generated in-repo `CHANGELOG.md` for **semver-releasing product repos** (templates, libraries, apps, and other `create-release` / release-please callers). **`homebrew-tap` and the monorepo site are deliberately out of scope** for this epic's first wave: the tap is cask-driven (no product `.releaserc`), and the monorepo docs site has no product release cutter. A later child may add a protection-friendly mechanism for those two if the epic is widened. Release automation must produce the file under PR-protected `main` without fighting branch protection or product-specific CD couplers.

## Decision

**Hybrid release architecture: release-please is the default in-repo CHANGELOG mechanism; semantic-release tag cutting stays only where CD depends on it.**

| Family | Mechanism | Constraint |
|---|---|---|
| **Default** (templates, libraries, aws, and other plain `create-release` callers) | **release-please** (`devantler-tech/actions` pattern) | Must produce `CHANGELOG.md` via release PRs; no direct commits to protected `main` |
| **`actions`** | release-please | Already ships `CHANGELOG.md` this way |
| **KSail** | semantic-release cuts tags for GoReleaser; `CHANGELOG.md` lands through a sequenced protection-friendly PR path that does **not** dual-own semver | Preserves `feat!` → major and Homebrew cask CD |
| **World at Ruin** | semantic-release draft-release → CD publish; `CHANGELOG.md` via the same protection-friendly PR path | Preserves immutable-release ordering (tag → attach → publish) |
| **homebrew-tap / monorepo site** | **Out of scope** for [#2269](https://github.com/devantler-tech/monorepo/issues/2269) until a later child widens the epic | Tap is cask-driven; monorepo site has no product `.releaserc` — not an unimplemented gap |

### Hard constraints

1. **Protected `main` forbids `@semantic-release/git`.** Active “Require a pull request before merging” rulesets with no bypass actors mean a plugin that commits `CHANGELOG.md` straight to `main` fails. Do not enable `@semantic-release/changelog` + `@semantic-release/git` on create-release repos under current rulesets.
2. **release-please is the proven in-repo path.** It opens `release-please--*` PRs, then tags after merge. CI and dependency-review already special-case those PRs.
3. **Semantic-release today writes Release bodies, not files.** Where notes-generator is present, notes go to GitHub Releases only. Extending semantic-release without a git commit still does not satisfy the epic’s in-repo file.
4. **Org shared `.github/.releaserc` stays analyzer-only** until consumers migrate; do not add git plugins there.
5. **Agents must not “just enable changelog+git”** on a create-release repo — that path is known-broken on protected `main`. Revisit only if the maintainer adds an explicit, least-privilege bypass for the release App.

## Consequences

- Implementation children under [#2269](https://github.com/devantler-tech/monorepo/issues/2269):
  1. [#2382](https://github.com/devantler-tech/monorepo/issues/2382) — migrate plain semantic-release repos to release-please.
  2. [#2383](https://github.com/devantler-tech/monorepo/issues/2383) — KSail: in-repo CHANGELOG without breaking GoReleaser / `feat!` majors.
  3. [#2384](https://github.com/devantler-tech/monorepo/issues/2384) — World at Ruin: in-repo CHANGELOG preserving draft-release → CD publish order.
- Portfolio default for new or migrating repos is the `actions` release-please layout, not semantic-release file plugins.
