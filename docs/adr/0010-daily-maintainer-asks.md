# ADR 0010 — Send daily only while unanswered asks exist

- **Status:** Accepted by direct maintainer direction
- **Date:** 2026-10-24
- **Deciders:** Maintainer; Agentic Engineer
- **Issue:** [#4475](https://github.com/devantler-tech/monorepo/issues/4475)

## Decision

Send the maintainer digest daily only while unanswered asks exist. Never repeat an answered ask.
This supersedes the weekly delivery cadence in [ADR 0009](0009-github-maintainer-asks-weekly-digest.md).
Its public-content boundary, GitHub notification delivery and reply rules still apply.

The workflow checks daily at 06:17 UTC. An assigned digest from the same UTC day prevents a
duplicate, including when closed. The sender reads direct maintainer replies on asks and numbered
answers on previous bot-created, assigned digests, open or closed. Agent output, other authors,
quoted examples and ambiguous mappings cannot answer a question. Reply text only suppresses a
repeated question here; executing a decision remains subject to the engineering contract.

When no unanswered asks remain, send nothing and close nothing. Dated changelogs stay pending.
The next digest with an ask combines them, using only reviewed, checked summaries. Successful
deliveries record each summary's date and exact hash in the generated issue body. Quiet days,
failed assignment and withheld content cannot mark a summary delivered. No separate state file
or external service is introduced. GitHub scheduling can be delayed; this is not an email SLA.

When all pending changelogs cannot fit in one email, send an oldest-first batch that fits and say
more remains. Record receipts only for that batch; keep the rest pending for later asks.

Summaries use their UTC delivery date as `docs/digests/YYYY-MM-DD.md`, and cover work since the
previous delivery. Existing ISO-week files and ADR 0009 remain historical records. If no pending
reviewed summary is usable, the sender still includes the current open asks and explains that
the work summary is missing. When some summaries are usable and others fail their checks, send
the usable batch with a notice that some content was held back.
